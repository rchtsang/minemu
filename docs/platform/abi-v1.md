# Platform ABI Version 1

> **Status: Historical normative.** This frozen document records the published
> Assignment 1 contract. New work targets [Platform ABI v2](abi-v2.md).

## Scope

The platform is a deterministic single-core A32 machine for operating-systems
coursework. It is not a model of a production SoC.

The keywords **MUST**, **MUST NOT**, **SHOULD**, **SHOULD NOT**, and **MAY** are
normative. Behavior not specified by a version-1 requirement is unspecified and
software must not depend on it.

| Specification | Contract |
|---|---|
| [Boot ABI v1](boot-v1.md) | Reset firmware, boot locations, kernel handoff, and boot info |
| [System-image format v1](system-image-v1.md) | Serialized image records and validity |
| [Exceptions and MMU ABI v1](exceptions-and-mmu-v1.md) | Exception entry, CP15, translation, and faults |
| [Device ABI v1](devices-v1.md) | MMIO and peripheral behavior |

**MINEMU-ABI1-SCOPE-001:** These versioned platform documents take precedence
over implementation comments, host-tool documentation, and informative guides.

**MINEMU-ABI1-SCOPE-002:** Rust APIs, Unicorn behavior, host operating-system
behavior, CLI policy, and reference-template choices are not ABI unless a
requirement explicitly incorporates them.

## Terminology

| Term | Definition |
|---|---|
| Physical address (PA) | Unsigned 32-bit address in the machine memory map |
| Virtual address (VA) | Unsigned 32-bit address generated by a CPU fetch, read, or write while translation is enabled |
| Physical range | Half-open byte interval `[start, end)` in PA space |
| Virtual range | Half-open byte interval `[start, end)` in VA space |
| ROM offset | Zero-based byte offset within Boot ROM or System ROM, not a PA or VA |
| MMIO offset | Zero-based byte offset within one device's 4-KiB MMIO page |
| LBA | Zero-based 512-byte logical block index on attached block media |
| Host-file offset | Zero-based byte offset in a host file; not guest-addressable |
| Tick | One unit of deterministic virtual time, not a cycle or wall-clock duration |
| Reset | Recreation of CPU, MMU, RAM, peripheral, and virtual-time initial state while retaining configured ROM contents |
| Direct map | Mapping from RAM PA to VA by adding `0x8000_0000` |

**MINEMU-ABI1-TERM-001:** Every range in the version-1 specifications is
half-open unless explicitly stated otherwise.

**MINEMU-ABI1-TERM-002:** Numeric addresses and sizes are unsigned. Serialized
integer fields have the widths and byte order stated by the image specification.

## CPU

| Property | Version-1 value |
|---|---|
| Processor count | One |
| Architecture/profile | ARMv7-A, Cortex-A9 compatible |
| Instruction state | A32 |
| Byte order | Little-endian |
| Supported modes | USR, SVC, IRQ, ABT, UND |
| Floating-point ABI | Soft-float |

**MINEMU-ABI1-CPU-001:** The machine MUST expose one little-endian ARMv7-A
Cortex-A9-compatible processor executing A32 instructions.

**MINEMU-ABI1-CPU-002:** Guest entry points MUST be four-byte aligned and guest
software MUST keep `CPSR.T` clear. Thumb execution is unsupported.

**MINEMU-ABI1-CPU-003:** USR, SVC, IRQ, ABT, and UND modes MUST provide the
architectural banked SP/LR and SPSR state used by the exception specification.

**MINEMU-ABI1-CPU-004:** Guest software MUST NOT depend on VFP, NEON, FIQ
delivery, TrustZone, virtualization extensions, caches, DMA coherency, or SMP.

**MINEMU-ABI1-CPU-005:** The supported source profile is freestanding A32 C and
assembly built with `-mcpu=cortex-a9 -marm -mfloat-abi=soft`. `libgcc` MAY be
linked statically; Newlib and newlib-nano are not platform dependencies.

## Reset State

| State | Reset value |
|---|---|
| `PC` | `0x0000_0000` |
| CPU mode | SVC (`CPSR.M = 0x13`) |
| Instruction state | A32 (`CPSR.T = 0`) |
| IRQ/FIQ masks | `CPSR.I = 1`, `CPSR.F = 1` |
| Translation | Disabled (`SCTLR.M = 0`) |
| `TTBR0` | `0x0000_0000` |
| `VBAR` | `0x0000_0000` |
| `DFSR`, `DFAR` | `0`, `0` |
| Virtual time | Tick `0` |
| RAM | All bytes zero before reset firmware executes |
| Boot ROM/System ROM | Configured bytes retained unchanged |
| Peripherals | Values listed in [Device ABI v1](devices-v1.md#reset-state) |

**MINEMU-ABI1-RESET-001:** Reset MUST establish every value in the reset-state
table. General-purpose and banked-register values not listed are unspecified.

**MINEMU-ABI1-RESET-002:** Reset MUST zero the complete RAM range before reset
firmware executes. A test harness MAY apply an explicitly configured RAM prefill
after platform reset; that harness action is not part of the guest ABI.

**MINEMU-ABI1-RESET-003:** Reset MUST retain the configured immutable Boot ROM
and System ROM bytes. Host block-media persistence across reset is host policy,
not physical-memory retention.

## Physical Memory Map

| Half-open PA range | Size | Access and purpose |
|---|---:|---|
| `[0x0000_0000, 0x0001_0000)` | 64 KiB | Read/execute Boot ROM |
| `[0x0800_0000, 0x0900_0000)` | 16 MiB | Read/execute System ROM |
| `[0x1000_0000, 0x1000_1000)` | 4 KiB | Interrupt controller MMIO |
| `[0x1000_1000, 0x1000_2000)` | 4 KiB | SysTick MMIO |
| `[0x1000_2000, 0x1000_3000)` | 4 KiB | Block-device MMIO |
| `[0x1000_3000, 0x1000_4000)` | 4 KiB | RNG MMIO |
| `[0x1000_4000, 0x1000_5000)` | 4 KiB | UART0 MMIO |
| `[0x1000_5000, 0x1000_6000)` | 4 KiB | UART1 MMIO |
| `[0x1000_f000, 0x1001_0000)` | 4 KiB | Trace MMIO |
| `[0x4000_0000, 0x4400_0000)` | 64 MiB | Read/write/execute RAM |

**MINEMU-ABI1-MAP-001:** The machine MUST implement the listed physical ranges.
Addresses outside them, including reserved pages in
`[0x1000_6000, 0x1000_f000)`, are unmapped and guest software MUST NOT access
them.

**MINEMU-ABI1-MAP-002:** Boot ROM and System ROM MUST reject writes. RAM MUST
permit reads, writes, and instruction fetches subject to MMU permissions.

**MINEMU-ABI1-MAP-003:** MMU control MUST be available only through the CP15
interface; no MMIO MMU-control page exists.

**MINEMU-ABI1-MAP-004:** The required RAM direct map is:

```text
VA [0xc000_0000, 0xc400_0000) -> PA [0x4000_0000, 0x4400_0000)
VA = PA + 0x8000_0000
PA = VA - 0x8000_0000
```

## Virtual Time

| Event | Tick cost |
|---|---:|
| Successfully completed ordinary or valid CP15 instruction | `1` |
| SVC or undefined instruction | `1`, followed by `1` for exception entry |
| Faulting fetch, data access, or invalid MMIO instruction | `0`, followed by `1` for abort entry |
| IRQ entry at an eligible instruction boundary | `1` additional tick |
| Host/backend failure after execution stops | `0` additional ticks |

**MINEMU-ABI1-TIME-001:** Virtual time MUST be a deterministic logical progress
counter. It is not a hardware-cycle or real-time model.

**MINEMU-ABI1-TIME-002:** The machine MUST apply the costs in the virtual-time
table. Device command instructions have only their normal instruction cost;
their asynchronous effects use deadlines defined by the device contract.

**MINEMU-ABI1-TIME-003:** Peripherals MUST process each newly reached tick before
the next guest instruction begins. Successful and guest-visible failed
asynchronous operations MUST complete at the same documented deadline.

**MINEMU-ABI1-TIME-004:** Pending IRQs MUST be delivered only at instruction
boundaries with `CPSR.I = 0`. A synchronous exception or fault at a boundary
takes priority over later IRQ delivery at that boundary.

**MINEMU-ABI1-TIME-005:** Execution that would advance virtual time beyond
`u64::MAX` is outside version-1 execution limits.
